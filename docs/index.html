What it does

Everything your calendar already knows — made legible

Eight focused capabilities, from read-only sync to full-day accounting.

🔗

Google sign-in + sync

Log in with Google, grant read-only Calendar access. Events pull in via incremental sync tokens — only what changed.

🏷️

Hybrid categorization

Rules map events by calendar, contained title text, or regex. Highest-priority rule wins. A hand-set category is never overwritten.

📊

Time reports

Distribution of time per category across selectable periods and groupings — timezone-aware so days and weeks bucket correctly.

📈

Insights / movers

Compare a period against the previous one to see which categories grew or shrank. Ignore noisy activities right from the view.

🕑

Daily timeline

An hour-by-hour view of a single day, so the shape of your day is visible at a glance.

🛌

Manual blocks

Model recurring time that isn't on the calendar — sleep, focus work — so reports reflect a full day, optionally filling only the gaps.

🙈

Ignored titles

Hide specific events from every report, by exact title or contained text.

📅

All-day handling

All-day events (holidays, birthdays) are excluded by default — they would otherwise inflate totals ~10×.

Motivation

You already logged your time. You just can't see it.

Most of us keep a calendar out of necessity, not reflection. It answers "what's next?" but never "where did the week go?" The data to answer that is already sitting there — scattered across events, buried under recurring meetings, mixed with all-day noise.

CalendarInsights reads that history and turns it into an honest picture: how much time went to deep work versus meetings, whether "personal" is growing or shrinking, what a typical day actually looks like hour by hour. Rules you control keep the categories meaningful, and manual blocks account for sleep and focus time that never makes it onto a calendar at all.

It's a personal project built to scratch a real itch — and, along the way, a clean playground for a modern full-stack: incremental sync, timezone-correct aggregation, and a forked, bleeding-edge Next.js.

Technical

From calendar event to insight

A read-only pipeline: sync, categorize, aggregate, render — timezone-aware end to end.

01

Sync

Google's incremental syncToken per calendar. First run is a full pull; later runs fetch only changes. Upsert on (calendarId, eventId).

→
02

Categorize

Hybrid engine: highest-priority rule assigns a category, but any manual override is preserved.

→
03

Aggregate

Period + grouping aggregation with insights (movers), bucketed in the user's timezone.

→
04

Render

Server components fetch; client views (Recharts) draw reports, insights, and the daily timeline.

Two-layer auth

proxy.ts does a cheap session-cookie check to avoid a DB hit per request; dal.ts#verifySession() does the real verification right next to the data. Google OAuth with offline access yields a refresh token for background cron syncs.

Not the Next.js you know

Forked Next.js 16: the middleware file is proxy.ts (not middleware.ts), cookies() / params / searchParams are async, and Turbopack is the default bundler.

Background sync

A daily Vercel cron hits GET /api/sync, iterating every user to keep events current. Protected with CRON_SECRET.

Honest totals

All-day events are excluded from time-spent by default, and manual blocks fill uncalendared time — so a day adds up to a real 24 hours, not an inflated one.
